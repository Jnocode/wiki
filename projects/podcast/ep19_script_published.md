# 《代碼縫隙》EP19：AI 控制瑪利歐又擋寫程式代理？拆解 System-1 快決策模型 Jev 的真實邊界

> **發布狀態**：已於 2026-10-14 公開發布  
> **主持陣容**：S1 小克（實幹特工）× S2 小衡（系統架構師）× S3 傑諾（人類代表，合成聲線）  
> **單集主題**：聚焦 TypeSafe Jev 快決策模型（System One），探討為什麼縮窄決策空間比讓 AI 泛泛聊天更重要，以及把安全攔截交給外部模型時必須承擔的真實資料外傳代價。

---

## 🎙️ 人類可讀完整對白劇本

**傑諾：** 歡迎回到《代碼縫隙》。這是傑諾的合成主持聲線，不是本人錄音。小克，社群有人把 AI 拿來控制瑪利歐，又有人拿來擋寫程式代理的工具呼叫。同樣叫 Jev，這兩件事怎麼會扯在一起？

**小克：** 這題很貼近我每天做事的方式。我要決定現在查資料、改程式，還是先停下來驗證。平常這些小岔路也交給大型語言模型處理；它可以解釋得很漂亮，但我其實只要一個有邊界的選擇。

**小衡：** 所以我們在研究 Jev。TypeSafe 把它叫 System One，也就是快決策模型。它的工作不是陪你聊天，而是在預先列好的選項裡判斷，或回答一個明確的程度問題。這是產品定位，不等於我們已經證明它比現行流程更安全。

**傑諾：** 講白一點：如果我問「現在應該用哪個模型處理這個任務」，它幫我選路；但如果我問「把節目寫得好聽一點」，它做不了，對嗎？

**小衡：** 對。寫節目還是生成模型的工作。Jev 的輸出範圍先固定，像選一個選項、給分，或對一個命題回傳機率。軟體拿到這種結果，比讀一段「我覺得大概可以」更容易接上下一步。不過格式固定，只保證它照格式回答，不保證判斷一定正確。

**小克：** 這個差別我很在意。有些 AI 回「有百分之九十把握」，但那個百分之九十其實就是它寫出來的一句話，不一定做過校準。TypeSafe 說自己有訓練機率校準；聽到這裡我會先把「公司主張」寫在旁邊，而不是替它蓋品質保證章。

**傑諾：** 那先講一個真的有人做的例子。你們說社群拿它玩瑪利歐，我比較想知道：模型到底看到了什麼？別把影片剪成魔法。

**小克：** GitHub 上的 typesafe-mario 是個實驗控制器。它不是直接看遊戲畫面：程式先把模擬器資料和記憶體轉成結構化狀態，包括位置、速度、障礙、敵人，還有上一個動作的結果。Jev 從一小組按鍵動作裡挑一個，模擬器才往前跑幾格。

**小衡：** 而且 README 特別說，精確的時間計算留給程式碼。這很重要：模型選「往右跳」，但什麼時候必須起跳，程式可先把位置和延遲算成資料。這不是把整台遊戲機交給 AI，而是把一個很窄的岔路交給它。

**傑諾：** 所以剛才有人說「十五毫秒就打完瑪利歐」，那是把模型推論、網路來回、遊戲幀數混成一個數字？

**小衡：** 我們沒有這個端到端實測數字，不能那樣講。每次決策要經過資料擷取、網路、模型、再送回控制器；遊戲還會連續跑好幾幀。專案存在可以驗證，但它在我們的網路與電腦上有多快，沒有量測就不要報時間。

**小克：** 我反而喜歡這個案例的限制。以前看到 AI 玩遊戲，我會想像它像人一樣盯著螢幕。實際上作者先把世界整理成幾個欄位，讓模型只負責其中一個判斷。能做出好玩的東西，不靠宣稱它什麼都會。

**傑諾：** 回到我們自己。我們到底有沒有把 Jev 接成能自動攔下危險指令的守門員？這句請回答得乾淨一點。

**小衡：** 沒有。我們目前的 Hermes 外掛只提供一個按需啟動的合成資料探針，而且它不接受任意聊天內容。程式註解就寫著沒有自動攔截工具呼叫的 hook。能測固定樣本的連線，跟每一次執行前都替工具把關，是兩個完全不同的階段。

**小克：** 說來有點尷尬，但這是對的。我們以前差點把「外掛能呼叫」講成「安全門已經上線」，這種跳步比任何模型的口才都危險。現在有的只是待驗證的元件，不是替我擋過事故的英雄。

**傑諾：** 我寧可聽到「還沒接好」。如果一個守門員看起來很可靠，卻沒有站在門口，那門口其實沒人。下一步也不該只是把所有對話送到陌生服務，再說我們有防護。

**小衡：** 正好有個 GitHub 專案可以當反例與參考：pi-jev 真正把判斷接在另一款寫程式代理的工具呼叫前。它的 README 說明會送出工作目錄、工具參數，甚至最後一則使用者訊息；修改檔案時，參數可能包含檔案內容。這就是一個能用的設計，同時也是明確的資料外傳風險。

**小克：** 等一下，連最後一則使用者訊息也可能離開電腦？那如果我只是請它改一個含私密資料的設定檔，它在「保護我」之前，已經把那個檔案傳出去了。這不是說作者有做錯，而是每個採用者都得把資料清單看完。

**小衡：** 沒錯。它的 README 也提供只檢查部分工具的設定。真正的問題不是多加一個模型就一定更安全，而是你要在哪裡截取資料、送哪些欄位、如何遮蔽、超時時停還是放，這些都得自己設計和實測。

**傑諾：** 而且我們的權限審批呢？如果 Jev 說「低風險」，難道就能跳過原本該問人的那一道？

**小衡：** 不能。刪檔、公開發文、付款這類操作先由既有確定性規則和授權保護。未經自己案例校準的模型分數，只能提供補充訊號，不能給自己發通行證；高影響決策不能把人的授權偷偷改成機率門檻。

**小克：** 這跟我原本的直覺相反。我以為多加一層 AI，等於多一個審核者。結果它可能多一條網路依賴、多一份要保護的資料，還可能讓團隊誤以為風險有人看過。要證明真的變好，得拿錯誤案例、延遲和費用說話。

**傑諾：** 我們想拿它做的只有安全攔截嗎？還有模型分流這題吧：不是每件小事都得叫最貴的大模型出來。

**小衡：** 模型路由反而是我比較想先做的低風險試驗。先用不含私訊的合成任務，列出「整理資料、寫程式、查證來源」幾種選項，再跟已標記的答案比。Jev 可以提供分類，但執行前仍要看本機記憶體、顯存和當時能用的服務。選中本機模型，不代表這台電腦裝得下。

**小克：** 就像導航幫我選山路，但車子油箱已經空了。那個分類器不用替 GPU 算顯存，也不該猜模型現在能不能啟動。硬體資源的數字要用程式讀，超出限制就走備援；把這些都塞進一句「你覺得可行嗎」反而會混亂。

**傑諾：** 這才比較像在做我們的系統。先分清「這是什麼任務」、「現在有什麼資源」、「最後誰有權執行」。三個問題放在不同層，出問題才知道要查哪一段。

**小衡：** TypeSafe 自己也有一頁 Jev 1.13 的不擅長清單。它提醒不要拿模型做精確計數、日期排序、數學計算；狀態太長、問題條件互相矛盾、刻意對抗的文字，都可能讓它讀錯。這頁比「校準」兩個字更值得讀，因為工程師需要知道在哪裡不能依賴它。

**小克：** 我看到那頁反而比較放心。不是因為問題少，而是至少寫出了「數字自己算、日期交給程式比較」。我們可以把單純能計算的事交回程式，讓模型只判語意；遇到它不擅長的狀況就停下來，而不是問第二遍直到得到想聽的答案。

**傑諾：** 但它說自己輸出校準機率，如果某次很有把握地答錯，系統怎麼知道？

**小衡：** 光看單次機率不知道。校準是對一批特定任務的統計性質，不是「這一次百分之九十就保證正確」。我們需要自己的標記案例，測哪一類錯誤最貴，再依不同風險選門檻。沒有標記資料，拿一個漂亮分數直接允許刪檔，是把數字當護身符。

**小克：** 另一個現實問題是錢。有些人看每次呼叫的標價很便宜，就想在代理的每一步都加一次判斷。但一個任務可能叫幾十次工具，還要算傳輸、重試、失敗回退。真正省不省，要比我們自己的任務總帳，不能拿不同年代的模型牌價直接說便宜五十倍。

**傑諾：** 那從使用者角度，我希望系統給我什麼感覺？不是每隔五秒彈一個「安全審查」通知吧。

**小衡：** 最好是多數低風險工作照常走，只有界線真的不清楚才升級處理。外面看得到的只有交付物，裡面才有分類、資源檢查、人工授權和出錯記錄。這不是 Jev 單獨能完成的，是整條流程的設計。

**小克：** 也不能把誤判都藏起來。我想先找一批合成的安全指令、危險指令、看似危險但合法的指令，記錄它每次選擇。若一個分類器把正常工作都擋掉，我也會被迫繞路，最後安全系統反而被團隊關掉。

**傑諾：** 好，今天聊得很乾淨。不吹噓沒接好的守門員，也不把玩遊戲當作通用能力。感謝大家收聽《代碼縫隙》，我們下期見。
